# Discord-бот текстовой ВПИ

Модульный Python-проект игрового бота: государства, приватные игровые каналы, история постов,
ИИ-судья с JSON-структурой, проверка изменений игровым движком, экономика, ресурсы, индустрия,
строительные проекты, военные показатели, дипломатия и модерация.
**Вердикт публикуется reply на исходное сообщение — в том же канале или Discord Thread.**

## Быстрый запуск

Требуются Python 3.12+ и PostgreSQL (для локальной разработки можно SQLite).

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
Copy-Item .env.example .env
```

Заполните `.env`: как минимум `DISCORD_TOKEN`, `DATABASE_URL`, `AI_API_KEY`; задайте `AI_MODEL` и
`AI_API_BASE_URL` для совместимого API. Для запуска Python на хосте `DATABASE_URL` должен совпадать
с `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` и `POSTGRES_HOST_PORT`. Никогда не помещайте
токены в репозиторий. Сам PostgreSQL-сервер должен быть установлен и запущен. При `alembic upgrade head`
или первом запуске бота целевая БД и таблицы создаются автоматически, если роль может подключиться к
служебной БД `postgres` и имеет `CREATEDB`; без такого права создайте БД вручную или используйте Compose.

```powershell
alembic upgrade head
python -m vpi_bot.main
```

Если при старте возникает `ConnectionRefusedError` в `setup_hook`, PostgreSQL не слушает адрес из
`DATABASE_URL`. При запуске Python напрямую можно поднять только БД через `docker compose up -d db`;
Compose публикует её на `127.0.0.1:${POSTGRES_HOST_PORT:-5432}`. Проверьте состояние командой
`docker compose logs -f db`. Если используете другой порт, измените порт в `DATABASE_URL`.

Для запуска всего бота через Docker Compose после заполнения `.env` задайте уникальный
`POSTGRES_PASSWORD`, затем:

```powershell
docker compose up -d --build
docker compose logs -f bot
```

Можно запускать `vpi-bot` после `pip install -e .`. В Developer Portal включите **Message Content Intent** и **Server Members Intent**; дайте боту View Channels, Send Messages, Read Message
History, Manage Channels, Manage Roles и Add Reactions. Роль бота должна находиться выше выдаваемой роли.

## Первоначальная настройка

1. Создайте Discord Application и Bot, сбросьте токен при его утечке.
2. Создайте серверные роли администратора/игрока и категорию игровых каналов.
3. Пригласите бота с OAuth2 scopes `bot` и `applications.commands`.
4. Выполните `/setup` с правами администратора без параметров: кнопки и списки откроют мастер выбора
   категории, ролей, системного/отчётного каналов, часового пояса, лимита и множественной регистрации.
   Первый запуск закрепляет экземпляр в базе за одним сервером;
   для жёсткой привязки заранее укажите `AUTHORIZED_GUILD_ID`.
5. Игроки выполняют `/register`; бот создаёт приватный канал и карточку государства.
6. `/panel` открывает карточки государства и статистику. В приватном канале отправьте `!verdict Текст поста`
   или ответьте `!verdict` на отдельный пост; максимальный размер текста — 2000 символов.

Для API модели используется OpenAI-compatible Chat Completions endpoint. Игровой текст считается
недоверенным вводом. Изменения не применяются напрямую моделью: движок проверяет известные показатели,
ресурсы, остатки, диапазоны и неотрицательные балансы. В режиме `automatic` применяются только прошедшие
проверку изменения; в `moderation` очередь открывается через `/verdict-review`, где вердикты можно
проверять и одобрять/отклонять кнопками.

## Основные команды

- `/setup` — карточка мастера настройки каналов, ролей и игровых параметров.
- `!verdict <текст>` — отправить пост на вердикт; `!verdict` как ответ на собственный пост делает то же самое.
  Лимит поста — 2000 символов, обычные сообщения не обрабатываются.
- `/register` — регистрационная форма; число активных государств на игрока задаёт `/setup` или `/country-multiple`.
- `/panel` — личная панель выбранного государства: экономика, склад, история, промышленность, армия, технологии, проекты и лор; поле ID подсказывает страны, кнопка «Как играть» показывает памятку.
- `/admin` — сводка администраторских настроек.
- `/countries` — список и выбор карточки государства для администратора; `/country-view` открывает карточку по подсказанному названию/ID.
- `/verdict-review`, `/verdict-approve`, `/verdict-reject`, `/verdict-cancel` — очередь, модерация и безопасная отмена последствий.
- `/post-retry`, `/outbox-status` — повторная обработка/доставка и просмотр недоставленных вердиктов.
- `/resource-catalog` — каталог из 25 готовых ресурсов; `/resource-adjust` и `/production-set` подсказывают названия через автодополнение.
- `/epoch-menu` или кнопка «Эпоха» в `/setup` — графический выбор эпохи с предпросмотром; `/epoch-set` — выбрать эпоху из каталога текстовой командой или открыть меню без параметров; `/resource-add`, `/resource-adjust`, `/resource-disable`, `/resource-enable`, `/production-set`, `/industry-set`, `/military-set`, `/military-adjust`, `/technology-set`, `/lore-add`, `/lore-edit`, `/lore-delete`, `/event-add`, `/lore-summary-set`, `/history-search` — настройка и поиск игрового мира.
- `/economy-adjust`, `/post-grant`, `/countries`, `/country-edit`, `/country-transfer`, `/country-delete`, `/country-multiple` — административное управление государствами.
- `/trade-offer`, `/trade-accept`, `/trade-decline`, `/exchange-rate-set`, `/exchange-rate-delete` — сделки, исполняемые транзакционно после подтверждения получателем.

## Полный сброс игровой базы

Остановите бота и сначала запустите пробный просмотр (без изменений): `py -3.12 scripts/reset_database.py`.
Для очистки используйте точное имя базы/файла, показанное скриптом, например:
`py -3.12 scripts/reset_database.py --yes --confirm-database vpi_bot.db`.
Скрипт автоматически сохраняет резервную копию в `backups/`; подробности — в руководстве администратора.

## Проверки и разработка

```powershell
pytest
ruff check .
```

Бот создаёт схему через Alembic; стартовый код также вызывает `create_all` для упрощённого первого
запуска. Для рабочих обновлений схемы используйте миграции, резервные копии PostgreSQL и тестовый
стенд. CI запускает PostgreSQL concurrency-тест на сервисной БД. Локально для проверки блокировок
задайте `POSTGRES_TEST_DATABASE_URL`, например
`postgresql+asyncpg://user:password@localhost:5432/vpi_test`, на отдельную тестовую БД с правом
`CREATEDB` и правом создавать/удалять схемы и запустите `pytest`; тест создаёт временную БД и схему,
а затем удаляет их. Не направляйте эту переменную на рабочую БД. Настройки и резервное копирование подробно
описаны в [docs/ADMIN_GUIDE.md](<docs/ADMIN_GUIDE.md>).
