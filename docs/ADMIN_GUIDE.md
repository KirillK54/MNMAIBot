# Руководство администратора

## 1. Discord Application и разрешения

На Discord Developer Portal создайте Application → Bot, получите токен и поместите его только в
`.env` (`DISCORD_TOKEN`). В OAuth2 URL Generator отметьте `bot` и `applications.commands`. Минимальные
права: View Channels, Send Messages, Read Message History, Manage Channels, Add Reactions, Embed Links;
для автоматической выдачи роли — Manage Roles, а роль бота поднимите выше роли игроков. Включите
Message Content Intent и Server Members Intent в настройках бота. Не публикуйте токен и ключ AI API; при утечке немедленно
сбросьте их.

## 2. База данных и запуск

Установите Python 3.12+, выполните команды README. Для PostgreSQL создайте отдельную базу и аккаунт
с минимальными правами. Установите `DATABASE_URL`, затем запустите `alembic upgrade head` и
`python -m vpi_bot.main`. Перед обновлением существующей БД сделайте проверенную резервную копию;
миграция `0002` добавляет недостающие текущие таблицы/поля без удаления данных, её downgrade намеренно
не удаляет схему. Локальный SQLite допустим только для разработки/тестов. Логи направляются
в stderr; задайте `LOG_LEVEL`.

## 3. API нейросети

Укажите `AI_API_BASE_URL`, `AI_API_KEY`, `AI_MODEL`, `AI_TEMPERATURE`, `AI_MAX_TOKENS`.
Адаптер ожидает OpenAI Chat Completions с JSON Schema. Выполните тестовый серверный пост сначала в
режиме модерации; сверяйте с правилами мира. Не вставляйте секреты/персональные данные в системные
правила. Изменения ИИ остаются только предложениями до проверки игровым движком.

## 4. Привязка, каналы и роли

На целевом сервере выполните `/setup` с Discord-правом Administrator без параметров: откроется
карточка мастера с кнопками выбора каналов, ролей и игровых параметров. Выборы сохраняются сразу;
для запуска игроков обязательно назначьте категорию каналов государств. Часовой пояс задавайте в формате
IANA (например `Europe/Saratov`). При необходимости задайте
`AUTHORIZED_GUILD_ID` перед первым запуском. Серверная конфигурация в БД закрепляет один Guild ID;
не добавляйте бота на посторонние серверы. Выбор категории/ролей передаётся через Discord-интерфейс.
В системном, отчётном и приватном каналах государства боту нужны `View Channel`, `Send Messages` и
`Embed Links`; `Missing Access (50001)` означает, что канал недоступен боту или бот отсутствует на сервере.
Экономический расчёт при этом уже сохранён, но неотправленный дневной отчёт автоматически не повторяется.

## 5. Игровая настройка

Команда `/setup` безопасно добавляет недостающие стандартные ресурсы и эпохи, не перезаписывая
настройки существующих записей. Зарегистрируйте тестовую страну через `/register`, проверьте приватность
канала и права модератора. Карточка панели открывается `/panel`. Установите эпоху командой `/epoch-set`, правила мира — `/game-rules`,
режим вердиктов — `/verdict-mode`. `/resource-catalog` показывает готовый каталог из 25 стандартных ресурсов; названия ресурсов
подсказываются автодополнением в `/resource-adjust`, `/resource-disable`, `/resource-enable` и `/production-set`.
Начальные запасы внесите `/resource-adjust`, задайте добычу
`/production-set country_id resource_name amount_per_tick interval_hours`; отключение/включение ресурса:
`/resource-disable` и `/resource-enable`. Добавляйте лор `/lore-add`.
Администратор может корректировать показатели `/economy-adjust`, выдавать лимит `/post-grant` и менять
глобальный лимит `/post-limit`. `/admin` показывает доступность БД, наличие ключа ИИ и счётчики недоставленных
ответов/ошибочных постов (сам секретный ключ не отображается). Данные стран редактируются через `/country-edit`, владение передаётся
`/country-transfer`, `/country-delete` архивирует страну и закрывает канал, сохраняя историю. Настройка
действующих предприятий доступна через `/industry-set` (JSON-рецепт ресурсов), а военные данные и технологии
— через `/military-set` и `/technology-set`; для дельт армии используйте `/military-adjust country_id section field delta reason`
(например, увеличить личный состав или сократить боеприпасы). Изменение военного бюджета автоматически
снимает/возвращает средства из казны. Лор редактируется командами `/lore-edit`, `/lore-delete`,
`/lore-summary-set`; отдельные события добавляются `/event-add`, ищутся `/history-search`. Память
автоматически компактизирует каждые десять событий в краткую extractive timeline. Для денежных сделок
между разными валютами настройте направленный курс `/exchange-rate-set from_currency to_currency rate`;
удалите его `/exchange-rate-delete`. AI может создавать строительные и исследовательские проекты в
вердиктах; строительство резервирует стоимость и материалы, а простое исследование не требует ресурсов
и завершается за 1–5 успешных ходов. Завершённый завод запускает производство, завершённая технология
открывает следующий уровень. На текущем этапе исследования намеренно упрощены; отмена уже завершённых
проектов/исследований недоступна. Боевая система не входит в текущий объём: администраторам достаточно
просматривать и корректировать показатели армии командами `/military-set` и `/military-adjust`.

## 6. Вердикты

Сначала установите `/verdict-mode moderation`; `/verdict-review` открывает интерактивную очередь:
выберите вердикт, просмотрите страну, игрока и исходный пост, затем используйте кнопки **Одобрить**
или **Отклонить** (с короткой причиной). Если нужен ручной вызов `/verdict-approve` или `/verdict-reject`,
список ожидающих вердиктов подсказывается в поле ID. Аналогично ID стран и сделок предлагаются
автодополнением. Ответы на исходные посты записываются в transactional outbox и автоматически
повторяются при временном сбое; очередь смотрите `/outbox-status`. Неисправимые Discord 4xx
(включая удалённый исходный пост) помечаются как `dead` и требуют исправления причины, затем
выберите сообщение из автодополнения `/post-retry`.
Администратор может применить `/verdict-approve ID`, отклонить `/verdict-reject ID причина`, отредактировать
карточку/последствия `/verdict-amend` или безопасно отменить уже применённые изменения через
`/verdict-cancel ID причина`. Корректировки сохраняют прежние значения в `audit_logs`. После тестирования
можно переключить `/verdict-mode automatic`; движок всё равно использует строгий allowlist и проверяет
лимит изменения, ресурсы и неположительные остатки.

## 7. Резервные копии и обновления

Для полного сброса игровых данных сначала остановите бота. Проверьте цель и число строк пробным запуском:
`py -3.12 scripts/reset_database.py` — он ничего не меняет. Для очистки повторите команду с `--yes`
и точным токеном из строки «Целевая база»; например, для SQLite по умолчанию:
`py -3.12 scripts/reset_database.py --yes --confirm-database vpi_bot.db`.
Перед очисткой скрипт автоматически создаёт копию в `backups/` и прекращает работу, если копию сделать
не удалось. Он очищает данные приложения, сохраняя схему и `alembic_version`. Для PostgreSQL необходим
`pg_dump` в `PATH`; токен подтверждения — имя базы, которое показал пробный запуск. После сброса снова
запустите бота и выполните `/setup`.

Для PostgreSQL задайте `PGHOST`, `PGPORT`, `PGUSER`, `PGDATABASE`, `PGPASSWORD` в защищённой среде
и выполните `./scripts/backup_postgres.ps1`. Скрипт создаёт custom-format dump в `backups/`; каталог
нужно шифровать и копировать за пределы сервера. Восстановление проверяйте на отдельной пустой БД:
`pg_restore --no-owner --no-acl --dbname <тестовая_БД> <файл.dump>`. Перед релизом: резервная копия →
восстановление на тестовой БД → миграция Alembic → pytest → обновление. Не выполняйте destructive
restore/`downgrade` на рабочей базе без проверенной копии.
